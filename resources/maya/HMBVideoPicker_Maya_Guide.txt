HMBVideoPickerLibrary

Primary workflow

1. In the VideoPicker widget, press BROWSE and select an existing Maya .mb or .ma file. The internal control invokes Griptape's native MAYA_SCENE FileSystemPicker and mirrors its absolute path into the widget.
2. Press READ beside the selected path. The widget submits the path through HMB_PICKER_COMMAND and the highest installed mayabatch opens the scene with script nodes disabled, preserves the scene-authored reference/proxy load state, and returns metadata only: camera information, the exact frame range and FPS, and an asset-root-only polygon Outliner. Referenced assets resolve to their highest loaded referenced DAG root; local scene collections such as CH, PR, or Objects_GRP expose only their immediate asset roots. Technical DUMMY, CheckBox, camera-helper, and GPU-cache branches are excluded. READ re-runs the same metadata scan. It does not render Viewport frames, invoke FFmpeg, create an original-playblast MP4, or automatically display an original video.
3. The Original, Mask, Depth, and Motion Guide checkboxes are inert output selections. Checking or unchecking any of them never launches Maya, FFmpeg, a cache lookup, or a render.
4. Press Generate Playblast to execute the checked outputs. A checked Original may reuse its validated cache, but every successful publication is copied to a new immutable catalog path. An unchecked cached Original remains on disk and does not create a new history asset.
5. Select a polygon group in the Picker Outliner.
6. Optionally assign Actor or Object/background Color Picks for the current Maya cut. These are authoring assignments, not properties of a numbered output slot. Color always remains assignment-only: unassigned and eye-disabled geometry is excluded, and zero enabled assignments produces a valid empty/black Color scope. When no Color Assignment exists, requested Depth and Motion Guide independently use every loaded, authored-visible, Picker-eye-enabled Maya asset they can process; they never force authored-hidden or eye-disabled geometry visible. When assignments are present, Actor Color Picks are unique, Object/background Color Picks may be reused across distinct Maya roots when several objects form one logical background mask, and duplicate roots or Asset IDs remain invalid technical ambiguities.
7. Select the camera, resolution, and any combination of the four outputs, then press Generate Playblast. At least one output must be checked.
8. Each successful checked result is appended to the current-cut history in generation order: Original, Mask (the legacy Color Assignment pass), Depth, then Motion Guide. It never replaces an earlier asset because of its role or number. Generated and imported MP4 assets may be selected independently. Up to ten selected cards can be drag-reordered; visible top-left-to-bottom-right order becomes transient @video1..@videoN. Deleting a card removes that catalog record without renumbering stored identities or deleting the media file. When fewer than ten are selected, a newly appended result is selected at the end; when ten are already selected, it remains available in history without displacing anything. Depth and Motion Guide retain typed provenance. When Mask is not selected, the renderer may still stage the legacy Color Assignment pass internally because those typed passes share its Maya session, but that staging pass is not appended. Depth is rendered with a temporary camera-space shader; no generated video is decoded or re-analyzed.
9. `PICKER_OUT` publishes metadata for the current ordered selection and `VIDEO_OUT` publishes the same paths as one `list[str]` generator connection. These are the Picker's only public outputs; there are no per-video output ports. The source Maya scene is never saved or renamed. All visibility, marker, and Depth shaders exist only in the temporary mayabatch session.

Maya compatibility

The Griptape host package requires Python 3.12, while its isolated Maya runner is release-gated against Python 3.11 grammar for Maya 2026's embedded interpreter. The Depth and Motion Guide paths use Maya commands and Python API 2.0 facilities documented for Maya 2026, including displaySmoothness and MItMeshEdge, and contain no Maya-2027-only version branch. This is a source/API compatibility gate, not a substitute for a live Maya 2026 workstation smoke test; release 0.4.19 was exercised against the supplied Jett scene in Maya 2027 because a Maya 2026 binary was not available on the validation workstation.

Picker notifications

The Picker has no bottom status footer and no floating warning bar. Operation status, success, warning, and failure notifications are appended to the fixed-height Activity Log, where error rows are red and the panel scrolls internally. Long Maya diagnostics are summarized for the node so they cannot cover or resize the Picker; the full diagnostic remains in the Maya log or artifact sidecar named by the operation.

Operation separation

READ is a metadata operation. It supplies the camera, frame range, FPS, and Outliner needed by the Picker without performing video generation.

Original Playblast is an optional, unmodified scene output. Its checkbox only selects the next Generate request, and its cache remains on disk while deselected. A successful checked Generate appends a new immutable Original catalog asset like the other three selected types; selection order alone determines its temporary @videoN token.

The Original control is intentionally not split into Proxy and Prop controls. A Maya proxy is a representation mechanism, while a prop is an asset role and can itself be represented by a proxy. Internally, the temporary Maya process separates the two loading contracts: each proxyManager keeps exactly one active representation, while ordinary prop and asset references, including nested references, are loaded normally.

Original, Snapshot, and Color PLAYBLAST use the best-effort viewport profile `hmb_full_smooth_geometry_v2`. The disposable Maya process preserves the scene-authored reference/proxy load and visibility state. On already loaded, authored-visible geometry it attempts Full display, disables distance LOD where supported, and requests Maya Smooth Preview 3 without saving those changes. A renderable shape with one verified authored material cutout is deliberately excluded from Smooth Preview so a textured mouth or eye card retains its authored silhouette and does not expose a smoothed cage boundary; `alpha_cutout_smooth_preserved_count` and the nested `cutout_transparency` audit make that exception explicit. For Original capture only, a mouth-semantic alpha card that proves the exact supported 7x7 grid, inner 5x5 UV patch, and resolved alpha bounds is duplicated at the evaluated frame, trimmed to its transparent-safe inner patch, rendered, and immediately removed while the source visibility is restored. The source Maya file is never saved. Missing high-proxy tags, unavailable references or plug-ins, unsupported drawables, and individual Smooth Preview failures are recorded as quality warnings; they do not prevent otherwise valid media from being rendered and published.

The Picker never forces an authored-hidden proxy, cache, stand-in, DUMMY/CheckBox branch, reference, or other DAG path to become visible. Already visible Bounding Boxes, caches, stand-ins, USD proxy shapes, and technical geometry may remain in the authored viewport representation when no better loaded representation is available, with an explicit quality warning. The tool continues to the achievable result instead of turning a preferred image-quality profile into an execution restriction.

Reference loading never executes embedded reference scripts. After the scene opens, every scene and UI script node in the disposable Maya session is neutralized before any timeline change or Viewport render; failure to neutralize one is a blocking diagnostic. The runner uses Maya's non-script proxy activation path and does not save these temporary safety changes back to the source scene.

Original preserves the scene's authored background, anti-aliasing, ambient-occlusion, motion-blur, lighting, material, and texture look. The shared full-smooth profile changes only representation-quality and Smooth Preview controls needed to prevent low-resolution or Bounding Box output.

The Original cache fingerprints the main scene and its discovered external dependencies, including ordinary and nested references, every proxy representation, file-backed textures, and cache files. A changed or missing dependency invalidates the cache. The generated MP4, runner sidecar, camera, frame range, FPS, resolution, frame count, dependency manifest, script-safety report, and quality profile must all validate before a per-scene publish lock atomically replaces the previous successful Original result.

All full-detail overrides occur only in the disposable mayabatch session and are restored before that process exits. The source Maya scene is never saved.

Mask is the existing Color Assignment playblast under its clearer output name. Generate Playblast uses the current cut's authoring assignments, visibility, camera, resolution, and READ frame metadata internally. Changing any output checkbox only updates the next generation request and never changes Color Pick assignments, catalog assets, PICKER_OUT, or VIDEO_OUT until Generate is pressed.

Mask / Color Assignment goal-first usage guidance (English)

Mask (the former Color Assignment playblast) is one optional source, but when it is animator-authored its readable frame-by-frame acting, motion, source-time mapping, pose, trajectory, contact, camera, framing, composition, visibility, occlusion, relative depth, and spatial arrangement are protected shot state by default. Proxy colors, Color Pick markers, temporary materials, dummy shading, and temporary Playblast lighting remain routing or control visualization rather than final appearance authority. It receives a temporary @videoN token only when selected, at its current drag order. It may be used directly, through a Motion Guide, together with images or other videos, or not used at all. Motion Guide and Depth are optional outputs rather than prerequisites. Image sheets, appearance bindings, Color Picks, and every other library input are also optional. Connecting any source adds available evidence only: it never makes another source, role, slot, binding, or companion mandatory and never stops generation merely because one is absent. A role label alone does not narrow animator-authored shot state, and an explicit scoped instruction may change only its named property for a named target or clearly scene-wide scope; if no temporal subset is stated or clearly implied, it applies to the whole shot, otherwise only to that subset. Technical media validation still protects files and timing, but it does not impose a required library combination.

Mask / Color Assignment 목표 우선 사용 안내 (한글)

Mask(기존 Color Assignment 플레이블라스트)는 프레임별 모션, 소스 시간, 카메라, 프레이밍, 구도, 공간 순서, 트랜스폼, 포즈, 궤적, 접촉, 가시성 및 가림을 제공할 수 있는 선택 소스 중 하나다. 선택한 경우 현재 드래그 순서에 따라 임시 @videoN 번호가 정해진다. 사용자의 목표에 따라 직접 사용하거나 Motion Guide로 변환하거나 이미지·다른 영상과 함께 사용하거나 전혀 사용하지 않아도 된다. Motion Guide와 Depth는 필수 조건이 아닌 선택 출력이며 이미지시트, 외형 바인딩, Color Pick 및 다른 라이브러리 입력도 모두 선택사항이다. 어떤 소스를 연결해도 사용 가능한 근거만 추가될 뿐 다른 소스·역할·번호·바인딩·보조 영상이 의무가 되지 않으며, 하나가 없다는 이유만으로 생성을 중단하지 않는다. 소스가 서로 다르면 사용자의 목표와 명시적 지시를 우선하고 각 소스가 유용한 범위를 정해 달성 가능한 결과를 계속 만든다. 파일과 타이밍을 지키는 기술 검증은 유지하지만 창작 권한이나 필수 라이브러리 조합을 강제하지 않는다.

Typed auxiliary catalog behavior (English)

New Picker generation appends successful checked outputs in Original, Mask, Depth, Motion Guide order. Any subset is valid and unchecked media creates no new record. The catalog can retain more than ten assets, while at most ten may be selected for Prompt and generator output. Selected cards are read left-to-right and then top-to-bottom; drag ordering immediately rebuilds dense @video1..@videoN positions without changing stable video UIDs. Existing assets are never moved, deleted, or overwritten merely because a new result was generated. The ordering convention grants no creative priority or authority. Downstream connections and manual Prompt video rows remain independently usable in arbitrary combinations.

타입 기반 보조 영상 카탈로그 동작 (한글)

새 Picker 생성 결과는 성공한 항목만 Original, Mask, Depth, Motion Guide 순서로 현재 컷 히스토리에 새 자산으로 추가된다. 체크하지 않은 항목은 새 레코드를 만들지 않는다. 카탈로그에는 10개보다 많은 영상을 보관할 수 있지만 Prompt와 Generator로 보낼 수 있는 선택 영상은 최대 10개다. 선택 카드는 왼쪽 위에서 오른쪽으로 읽고 다음 줄로 내려가며, 드래그한 순서에 따라 @video1..@videoN이 연속으로 다시 정해진다. 이때 영상의 고유 UID는 바뀌지 않으며 기존 파일이나 자산은 새 생성 때문에 이동·삭제·덮어쓰기되지 않는다. 이 순서는 연결을 단순화하는 규칙일 뿐 창작 우선순위나 권한을 부여하지 않으며 다른 HMB 라이브러리의 존재를 요구하지 않는다.

Depth is an optional typed catalog asset, not an Original preview mode. Its stable identity is its video UID; it receives a transient @videoN position only while selected, and its typed authority remains attached to that exact UID and non-empty generation identity regardless of later drag ordering. The renderer may still stage the legacy Color Assignment pass internally because the typed passes share one disposable Maya session, but an unchecked Mask is never appended to the catalog or exposed through PICKER_OUT/VIDEO_OUT. Depth is produced without decoding or re-analyzing any video and without an Advanced Media, AI, or depth-estimation plug-in. It uses the exact Color Picker material-assignment path: 256 shared grayscale `surfaceShader`/shading-group buckets are created, and every visible polygon-mesh or NURBS-surface full DAG instance path receives the bucket for its current distance on every requested output frame. Depth v7 preserves an authored, resolvable cutout-alpha signal through the temporary grayscale shader assignment, so a mouth, eye, foliage, or other textured card does not become an opaque rectangle. The Sidecar audits cutout-alpha discovery and preservation; an ambiguous or unresolvable required cutout fails closed instead of silently publishing opaque geometry. The representative object distance is the median of the positive active-camera-space depths of the eight `exactWorldBoundingBox` corners, with the bounding-box center used only when no corner has positive camera depth. Animated visibility, template state, and every requested output frame are evaluated. Each raw interval is intersected with that frame's animated camera clip range; the lateral bbox gate uses the requested output raster aspect for both perspective and orthographic cameras and safely disables itself for unsupported camera 2D transforms. Geometry certainly outside the camera frustum is excluded. A bbox is only a conservative prefilter: Depth v7 deterministically samples up to 128 API mesh vertices and 64 polygon centers, then admits a normalization candidate only when at least one sampled surface point is inside the active camera raster and clip range. When Actor markers exist, only Actor shapes pay this precise sampling cost; assigned context remains fully shaded, rendered, and audited without entering the normalization population. A scene without Actor markers samples the generic visible scope. If Maya mesh sampling or the camera screen transform is unavailable, the validated bbox gate is retained as a conservative fallback and the Sidecar records that fallback. Sidecar representative outcomes use disjoint normalization accounting: screen-rejected means precise sampling ran but no point entered the raster/clip range, while role-excluded means Actor-priority context was deliberately not sampled. Foreground candidates, context candidates, screen-rejected samples, and role-excluded context never overlap and together equal the representative sample count. Depth v7 derives the fixed complete-sequence normalization window from the 1st and 99th percentiles of screen-valid Actor-marker representative depths. This prevents an offscreen character bbox, whole set, dome, or distant map from consuming the useful signal range. A scene without screen-valid Actor samples uses a robust 95th-percentile screen-valid shape fallback only when no Actor marker population exists, and a small scene uses its screen-valid representative extrema. The camera origin remains distance zero and the animated camera clip planes remain hard safety boundaries. The 256 material buckets span the full usable output interval 0.0 through 0.9. Values above 0.9 through 1.0 remain unused as a camera-near/bounds-approximation safety margin. An image plane attached to the active camera and any visible surface drawable that cannot receive and verify the plug-in-free shader fail closed; plates attached only to other cameras do not block the pass. Assignment verification covers every full DAG shape path on every rendered output frame. Depth of Field, hardware fog, SSAO, motion blur, multisampling, line antialiasing, and the output color transform are all verified disabled so authored viewport post effects cannot mix the raw distance values. No distance from a reference shot is hard-coded. One complete-sequence near/far range is fixed for every rendered frame, preventing normalization flicker. The bucket index follows a fixed monotonic linear camera-space curve (`normalized_power`, `contrast_exponent=1.0`). Effective near foreground reaches 0.9, effective far foreground reaches 0.0, context beyond the window clamps to black, and empty background remains pure black. The Depth sequence keeps the generation session's exact camera, frame map, FPS, duration, and raster and is encoded directly at that rate; no Change Speed node is required.

Only Maya `mesh` and `nurbsSurface` shapes can enter the Depth shader and verification scope. NURBS controller curves, locators, lights, and other unsupported drawables are excluded before assignment; the node receives only a compact unsupported-control count while the full type/path audit remains in the sidecar and Maya diagnostic log.

Image-style mouth alpha cards are always excluded from Depth. They are removed before Depth range analysis and shader assignment, hidden on a temporary Depth-only display layer, and recorded as count/reason evidence in the sidecar. The original display-layer membership is verified and restored when the Depth pass ends. No mouth card can fall back to an opaque Depth bucket, and Motion Guide receives no temporary mouth geometry or visibility state. Original alone may use the separately verified capture-only inner-patch correction described above.

Motion Guide v5 uses a compact core-control skeleton and adds evaluated facial motion without exposing the production rig. For each target it first reads weighted skinCluster influences from that target's actual render-scope meshes; rigs without enough usable local influences fall back to direct descendants and, only for Character or untyped standalone targets, that target's reference/namespace joints. Object/background markers can never trigger that fallback, and identical skeleton signatures are de-duplicated. Micro facial joints, finger detail, IK/FK drivers, dense twist/non-roll chains, corrective helpers, and cloth/accessory joints are excluded before selection; one weighted limb-segment twist sample may be retained when it is the rig's only usable elbow or knee representation. Stable joint IDs are retained separately from human-readable labels. Character Color markers may produce the core skeleton; Object/background markers remain rigid-transform targets. A target is drawn only while its root and at least one associated render shape satisfy the inherited Maya and Picker visibility state. Core body joints remain a motion-intent guide through self-occlusion.

The only accepted Motion Guide profile is `hmb_target_neutral_motion_guide_v5`, and its Sidecar uses `hmb-maya-motion-guide` schema version 2 with face-semantics schema version 2. It records each final evaluated Blend Shape weight as its unmodified raw numeric value and records connected numeric NURBS-curve controller plugs only as raw-value provenance. Raw NURBS controller-curve geometry is never rendered. Facial anchors are localized read-only from authored Blend Shape target-delta heatmaps on the selected deforming face mesh. When those landmarks do not provide an eyelid region, v5 may add bounded real vertices and topology edges only from render-scope, non-intermediate, deformed, authored-visible semantic eye or eyelid meshes (`render_scope_nonintermediate_deformed_visible_semantic_mesh_edges`). Alpha-driven cards are explicitly excluded, and the per-target `face_semantic_surface_audit` records candidates, accepted surfaces, limits, landmarks, edges, regions, and rejections. A missing bilateral side anchor is completed only when two other authored left/right semantic pairs agree on a bounded same-surface lateral offset; this is not a topology-symmetry claim. Jaw left/right anchors use a local face axis derived from authored upper-face and mouth anchors. If jaw center remains missing after both jaw sides are available, its same-surface vertex first tries their midpoint and must lie below mouth center, stay near the semantic lateral center, remain inside the left/right jaw span, and pass the bounded surface-snap checks. A direct mouth-center candidate at -up*0.10 face diagonal is subject to those same gates. If both candidates fail on a muzzle-like face, the last fallback retains the actual bilateral jaw midpoint's non-lateral surface profile and changes only its semantic up coordinate by the mean of the independently measured left and right mouth-to-jaw downward progress. Both side progresses must be bounded and agree within 0.05 face diagonal. Because a protruding or asymmetric mouth:center vertex is not reliable lateral-center evidence for that jaw profile, this final candidate's lateral drift is measured from the actual L/R jaw midpoint and is still limited to the smaller of 0.04 face diagonal or 25 percent of jaw span; span position 0..1 and the 0.06-diagonal surface-snap bound remain mandatory. The nearest surface vertex has no special authority: all vertices inside that same snap sphere pass through the unchanged gates first, and the eligible vertex with the smallest `(surface distance, vertex index)` tuple is selected. No eligible vertex remains a fail-closed result. Accepted and rejected profile candidates record total/scanned/eligible counts, selection score, downward, jaw-midpoint drift, mouth-center drift/offset, span position, jaw span, and snap fractions in the Sidecar audit. The face raster is limited to semantic left/right brow, eyelid, mouth, and jaw landmarks; brow is RGB 176/96/255, eyelid is 48/196/255, mouth is 255/72/180, and jaw is 255/176/64. A facial contour is rendered only when both endpoints of one declared face edge are front-facing and active-camera rays confirm both endpoints as first visible hits on the authored-visible character target meshes. Unknown Blend Shape aliases and their evaluated values are preserved in the Sidecar only and are never guessed into raster landmarks. Frame-local DAG visibility caching, once-per-frame occluder filtering, and projection-before-ray selection reduce repeated Motion Guide work without changing body-joint continuity or first-hit visibility rules. The full per-frame `motion_frames` array is retained in the on-disk sidecar only; retained node state and `PICKER_OUT` carry a compact report without frame rows. The immediately preceding v4 identifier is retained only for cleanup and diagnostics, not compatible typed-media or Prompt authority; v2 and v3 remain fully retired. Newly generated Motion Guide companions use v5 and Sidecar schema version 2.

Color, Depth, and Motion Guide MP4/sidecar pairs are staged, validated, encoded, and published per artifact. Validation still checks the exact camera, FPS, start/end frames, frame map, actual PNG raster size, typed guide semantics, and final H.264 stream frame count/rate/raster/BT.709 tags before that artifact is published. Every frame-folder and sidecar path returned by the Maya runner must exactly match its requested normalized staging path before it can enter cleanup or downstream I/O. FFprobe is used when available; an FFmpeg showinfo decode performs the same mandatory stream check when only the pinned imageio-ffmpeg binary is installed. A Depth or Motion failure simply prevents that new artifact from entering the catalog while valid Color and the other successful companion continue through their own atomic publication; every earlier catalog asset and selection remains untouched. Each media/sidecar pair and its Griptape project copy has isolated rollback data under the scene-scoped publish lock; a failed new project file is removed and no existing catalog asset is overwritten. HMBPromptLibrary adds matched-bundle confidence only for companions that actually committed with matching type, provenance, stable UID linkage, and non-empty bundle identity. Drag reorder changes only transient @videoN positions and never releases or reassigns that UID-scoped identity. Deselecting keeps the UID settings dormant for an exact later reselect; deleting removes only that catalog row, while a later generation or an optional companion failure leaves every earlier asset and relationship untouched. By default, generated typed companions add no automatic markers, Snapshot, Color Pick, identity, appearance, shading, or final-look instruction. An explicit scoped instruction may use a named readable property only for its named target or clearly scene-wide scope; if no temporal subset is stated or clearly implied, it applies to the whole shot, otherwise only to that subset, without promoting unrelated attributes.

Proxy encoding and timing

Original, Color, and generated typed companion PLAYBLAST MP4 files use the production high-quality profile `hmb_hq_bt709_crf6_v1`: H.264 High Profile Level 4.2, libx264 slow preset, CRF 6, yuv420p, BT.709 limited range, one-second closed GOP, one B-frame, two reference frames, and fast-start MP4 metadata. This profile was cross-checked against the approved 1280 x 720, 25 FPS, high-bitrate H.264 proxy reference; a 198-frame re-encode retained all 198 unique source frames, produced uniform timestamps and the exact 7.92-second source duration, and measured PSNR 54.737 dB / SSIM 0.999403.

The encoder receives Maya's native FPS as an exact rational input rate, writes an integer MP4 track timescale, uses frame passthrough rather than `-r`, and writes exactly the PNG count returned by Maya. Encoding may change compression and pixel representation only. It must never interpolate, drop, duplicate, reorder, retime, crop, or reinterpret motion. A cached Original created under an older encoding profile is invalidated and regenerated only when Original is checked and Generate Playblast is pressed.

The seven Actor colors and the three shared Ghost colors (Sky Blue, Mint, and Beige) use the same Maya Lambert material under Default Lighting and Shaded And Textured mode. The approved production profile is color_stable_lambert_profile: Lambert diffuse 0.55 with zero ambient-color gain and a 0.25 same-color incandescence gain. This preserves smooth three-dimensional form while lifting the unlit color floor so dense foliage and back-facing surfaces do not collapse into near-black regions. It uses Maya's native shaded silhouette without a pfxToon node. Controlled production-scene A/B validation found the legacy pfxToon rim visually indistinguishable while it added substantial per-frame evaluation time, so the Picker default remains native Lambert. The legacy character_outline_mode=pfx_toon path remains available only for Actor diagnostic comparison and is recorded truthfully in the sidecar when explicitly requested. Viewport multisampling and line AA remain off to match the approved playblast.

The four visible patterns use the production profile hmb_maya_world_root_projection_v1. Maya creates temporary Surface Shader projection graphs in the disposable render process: Floor Grid uses top-planar XZ projection, while Direction Checker, Sky Grid, and Position Pattern use triplanar XYZ projection. The projector is bound at the first output frame to the selected background root, follows its translation, rotation, and scale, and is never linked to the output camera. Inverse scale compensation keeps the pattern cell at 5 Maya world units, which is the approved 3x density relative to the 15-unit baseline. Camera and background motion therefore produce real perspective and surface flow instead of a frame-locked canvas.

These projection graphs do not read, create, or modify mesh UVs. Authored UV sets, references, materials, and source scenes are never saved; cutout transparency is preserved through temporary shader variants. Maya still renders the real full-detail Smooth Preview 3 geometry, animation, visibility, depth, occlusion, and final camera perspective. Snapshot and Color Playblast validate the world-pattern profile and runner report before publication. Original Playblast is never pattern-processed. The retired hmb_screen_space_pattern_post_v2 profile remains only as an explicit legacy fallback and is never silently mixed with the world-projection profile.

Prompt and Agent linkage

PICKER_OUT may be connected to HMBPromptLibrary PICKER_IN when automatic selected-video metadata synchronization is useful; the connection is optional. Any selected video may be connected and used in the way that best serves the user's goal. A connection adds information but never creates a requirement for another source, type, binding, or library. Missing or incomplete optional sources do not stop generation. When metadata is incomplete, preserve the usable source and continue with the user's explicit intent; reject only media that is technically unreadable or unsafe to process.

PICKER_OUT schema v5 publishes only the selected catalog records in visible row-major drag order, with stable `video_uid`/`source_uid`, dense transient `selection_order` and `video_slot`, resolved video paths, typed auxiliary provenance, Asset ID, Color Pick, Maya DAG root, Maya UUID, camera, and compact intrinsic generated-guide metadata. The catalog itself may retain more than ten assets, but the synchronized PICKER_OUT and VIDEO_OUT snapshot contains at most ten. When an Asset ID matches an active Image Name, HMBPromptLibrary can associate them automatically; a missing match remains valid and simply contributes no automatic image association.

HMBPromptLibrary alone owns Main Type, Target, Image Sub Type, Video Sub Type, Keep Out, VIDEO VFX, and descriptive control data. PROMPT_OUT contains only the user-verifiable Target Generator, Image Source, Image Role, Replacement Binding, and Video Source sections; descriptive control data, diagnostics, connected-source fallback metadata, and policy prose remain local or runtime-only. On the canonical direct Prompt edge, HMBAgentLibrary receives that public output, applies the signed Agent v4 project and shot rules only at runtime, executes the native Agent once, and removes hidden policy data from visible output.
