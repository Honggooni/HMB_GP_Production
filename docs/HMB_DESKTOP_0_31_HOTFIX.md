# Griptape Desktop 0.31.0 장애 보고서

HMB Team v0.9.43은 Windows Desktop 0.31.0의 Editor 0.132.0, SDK 0.106.0, Engine 0.113.0에 대응합니다. 기존 팀원은 라이브러리의 **Git Update/Override**를 실행하고 작업을 저장한 다음 Desktop을 완전히 종료하고 다시 실행합니다.

| 증상 | 확인한 원인 | 수정 및 확인 |
| --- | --- | --- |
| 모든 HMB 헤더가 기본 UI로 돌아가고 로동마트가 열리지 않음 | Desktop 업데이트가 편집기 시작 파일과 JavaScript 번들을 교체했습니다. 이전 HMB 배포본에는 새 번들의 식별값과 시작 화면 연결 코드가 없어 공통 UI 확장을 적용할 수 없었습니다. | 새 공식 번들에서 11개 HMB 헤더를 연결하고, 로동마트가 워크플로를 열어 샷 바구니를 준비하도록 수정했습니다. 전체 편집기를 Chromium에서 열고 시작 카드, 워크플로 생성, 프로젝트 선택, 닫기와 다시 열기를 확인했습니다. 이 검사에서 Desktop 부모 창과 엔진 응답은 시험용으로 제공했습니다. |
| 로동마트가 새 빈 작업공간을 거절함 | 기존 샷 바구니는 이전 엔진의 내부 흐름 목록을 읽었습니다. 새 엔진에선 각 워크플로가 이 목록을 갖습니다. 또한 기존 요청 처리는 화면에서 전달한 이름으로 대상 워크플로를 다시 찾았습니다. | 샷 바구니가 요청을 보낸 워크플로의 흐름과 노드를 검사합니다. 실제 엔진에서 두 탭을 열고 한 탭에만 노드 6개가 준비되는지, 다른 탭 이름을 섞은 요청을 거절하는지 확인했습니다. |
| Agent와 Generator 실행 전에 요청이 차단됨 | 새 엔진은 열린 워크플로마다 별도로 노드를 관리합니다. 기존 HMB 공통 검사가 엔진 핸들러보다 먼저 현재 워크플로를 지정하지 않고 노드 이름을 조회했습니다. 실제 Generator 실행 로그에 노드를 찾지 못한 오류가 두 번 남았습니다. 두 워크플로에 같은 이름의 Agent가 있을 때 다른 탭의 연결 해제 상태가 정상 탭까지 막는 문제도 재현했습니다. | 실행·연결·삭제 전 검사가 요청에 지정된 워크플로를 사용하도록 수정했습니다. 설치된 엔진에서 동명 노드를 두 탭에 만들고 Agent와 Generator가 각 탭의 연결 상태를 따르는지 검사했습니다. 실행 대상을 시험 콜백으로 연결해 유료 호출을 피했습니다. |

### 이전 검사가 놓친 부분

기존 검사는 당시 지원한 SDK와 편집기 조합을 기준으로 실행했습니다. 라이브러리 11개의 등록과 개별 위젯 동작을 확인해도, 새 Desktop이 HMB 화면을 여는지 또는 새 엔진이 버튼의 요청을 올바른 탭에 보내는지까지 확인할 수는 없었습니다. 공식 Stable 변경을 감지하는 검사는 팀 릴리스 게시를 제어합니다. 작업 PC의 Desktop 업데이트는 별도로 이루어집니다.

문제가 발생한 작업 PC에서는 11월 24일 10시 35분에 Desktop이 0.30.4에서 0.31.0으로 바뀐 기록을 확인했습니다. 이 PC에는 HMB 배포 안내에서 사용하는 Windows 자동 업데이트 보류 정책 파일과 사용자 환경 변수 설정이 없었습니다. 팀원 개별 PC의 설정은 이번 확인 범위 밖입니다.

### 이번에 추가한 배포 검사

- 공식 편집기 파일에서 HMB 후보를 생성하고 배포본에 기록된 해시와 대조합니다. 새 편집기의 실제 진입 화면에서 로동마트 버튼을 눌러 워크플로 생성 1회와 해당 워크플로의 샷 바구니 준비 1회를 확인합니다.
- SDK 0.106.0과 Engine 0.113.0에서 동명 노드의 탭 격리, Agent·Generator 실행 요청, Standard Agent 모델 선택과 실행 경계를 검사합니다. 이전 SDK의 회귀 검사도 함께 실행합니다.
- 앞으로 Desktop이 다시 바뀌면 새 공식 배포본으로 이 경로를 재검증해야 합니다. 이번 검사는 실제 팀원 PC에서의 재시작이나 외부 제공자의 유료 영상 생성 결과까지 보증하지 않습니다.
